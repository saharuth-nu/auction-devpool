# 01 บัญชีและการตรวจสอบคุณสมบัติ

## AUTH — เข้าสู่ระบบและบัญชี

| รหัส | Requirement | สถานะ |
|---|---|---|
| AUTH-01 | ระบบต้องมีหน้า login ของ admin โดยกรอก username และ password | ✅ |
| AUTH-02 | ระบบต้องมีหน้า login ของผู้ใช้ โดยกรอก username และ password แยกจากหน้า admin | ✅ |
| AUTH-03 | ระบบต้องมีหน้า register ของผู้ใช้ โดยกรอก fullname, username, password, email | ✅ |
| AUTH-04 | username ต้องไม่ซ้ำกันทั้งระบบ (ทั้ง admin และผู้ใช้) | ⚠️ |
| AUTH-05 | email ของผู้ใช้ต้องไม่ซ้ำ และมีรูปแบบถูกต้อง (ยังไม่ต้องยืนยัน email ใน M1) | ⚠️ |
| AUTH-06 | password ต้องยาวอย่างน้อย 8 ตัวอักษร | ⚠️ |
| AUTH-07 | admin ต้องสร้างบัญชี admin อื่นได้ | ✅ |
| AUTH-08 | admin มี **ระดับสิทธิ์เดียว** (ทุกคนทำได้ทุก module) | ✅ |
| AUTH-09 | admin คนแรกต้องสร้างจาก seed ไม่มีหน้า register ของ admin | ⚠️ |
| AUTH-10 | บัญชีผู้ใช้ไม่สามารถเข้าหน้า admin ได้ และกลับกัน | ⚠️ |
| AUTH-11 | ระบบต้องมี logout | ⚠️ |
| AUTH-12 | หน้า register ต้องมีช่องยินยอม **เงื่อนไขการใช้งานและนโยบายความเป็นส่วนตัว (PDPA)** ต้องติ๊กก่อนจึงสมัครได้ และระบบบันทึกเวลาที่ยินยอม | ⚠️ |
| AUTH-13 | ผู้ใช้และ admin ต้องเปลี่ยนรหัสผ่านของตนเองได้ โดยต้องกรอกรหัสผ่านเดิมก่อน | ⚠️ |
| AUTH-14 | admin ต้อง **ระงับ / ปลดระงับ** บัญชีผู้ใช้ได้ โดยต้องระบุเหตุผล ผู้ใช้ที่ถูกระงับ login ได้แต่เห็นเฉพาะหน้าแจ้งว่าถูกระงับพร้อมเหตุผล เข้าร่วมประมูลและยื่นราคาไม่ได้ | ⚠️ ดู open item O-10 |

**เกณฑ์ตรวจรับ:** register ได้เมื่อข้อมูลครบและถูกต้อง · username/email ซ้ำแล้วแจ้ง error ใต้ช่อง · ผู้ใช้เปิด `/admin` ไม่ได้ · login ผิดแจ้งข้อความโดยไม่บอกว่า username หรือ password ผิดข้อใด

## QUAL — การตรวจสอบคุณสมบัติ

| รหัส | Requirement | สถานะ |
|---|---|---|
| QUAL-01 | หลัง register สำเร็จ ผู้ใช้ต้องมีสถานะ **"รอการตรวจสอบคุณสมบัติ"** | ✅ |
| QUAL-02 | เมื่อ login ครั้งแรก ผู้ใช้ต้องกรอก **ทรัพย์สินที่ครอบครอง** เป็นรายการ แต่ละรายการมี ชื่อ และ มูลค่า (ตัวเลข บาท) อย่างน้อย 1 รายการ | ✅ |
| QUAL-03 | ไม่ต้องแนบเอกสารประกอบทรัพย์สิน | ✅ |
| QUAL-04 | เมื่อผู้ใช้กด submit ทรัพย์สิน สถานะต้องเป็น "รอ admin ตรวจ" | ✅ |
| QUAL-05 | ผู้ใช้ที่ยังไม่ผ่านการตรวจ (ยังไม่กรอก / รอตรวจ / ไม่ผ่าน) **ต้องทำอะไรไม่ได้เลย** เห็นเฉพาะหน้าสถานะของตนเอง | ✅ |
| QUAL-06 | หน้าสถานะต้องแสดงตามสถานะ: ยังไม่กรอก → ฟอร์มกรอกทรัพย์สิน · รอตรวจ → ข้อความ "อยู่ระหว่างการตรวจสอบคุณสมบัติ" · ไม่ผ่าน → เหตุผลและฟอร์มแก้ไข | ✅ / ⚠️ (ส่วนไม่ผ่าน) |
| QUAL-07 | admin ต้องดูรายการผู้ใช้ที่รอตรวจ ดูรายการทรัพย์สินของแต่ละคน และกด **ผ่าน / ไม่ผ่าน** ได้ | ✅ |
| QUAL-08 | เมื่อ admin ไม่ผ่าน ต้องระบุเหตุผล และผู้ใช้ต้องเห็นเหตุผลนั้น | ⚠️ |
| QUAL-09 | ผู้ใช้ที่ไม่ผ่านต้องแก้ทรัพย์สินและส่งตรวจใหม่ได้ | ⚠️ |
| QUAL-10 | เมื่อผ่านแล้ว ผู้ใช้ต้องเข้าหน้าแรกและใช้งานเต็มรูปแบบได้ | ✅ |
| QUAL-11 | **มูลค่าทรัพย์สินรวม** (ผลรวมทุกรายการ) ของผู้ใช้ที่ผ่านแล้ว คือเพดานของราคาที่ยื่นได้ (ดู BID-04) | ✅ |
| QUAL-12 | หลังผ่านแล้ว การแก้ไขทรัพย์สินต้องไม่ทำได้ใน M1 (กันการแก้เพื่อเพิ่มเพดานหลังตรวจ) | ⚠️ |

**เกณฑ์ตรวจรับ:** ผู้ใช้ที่ยังไม่ผ่านเปิด URL ฝั่งผู้ใช้ใดก็ตาม (หน้าแรก, สินค้า, ห้อง, ผลประมูล, request ยื่นราคา) ถูกส่งกลับหน้าสถานะทั้งหมด · ทรัพย์สินมูลค่าติดลบหรือไม่ใช่ตัวเลขถูกปฏิเสธ

**สถานะผู้ใช้:** `ยังไม่กรอก` → `รอตรวจ` → `ผ่าน` | `ไม่ผ่าน` (→ แก้แล้วกลับเป็น `รอตรวจ`) · admin ระงับบัญชีได้จากทุกสถานะ (AUTH-14) ปลดระงับแล้วกลับเป็นสถานะเดิม
