# 05 Non-Functional Requirements

| รหัส | Requirement | สถานะ |
|---|---|---|
| NFR-01 | ภาษาของระบบทั้งหมดต้องเป็น **ภาษาไทย** และใช้ **สกุลเงินบาท** | ✅ |
| NFR-02 | เวลาแสดงผลใช้เขตเวลา Asia/Bangkok และรูปแบบวันที่ไทยอ่านง่าย | ✅ |
| NFR-03 | การตัดสินเวลา (เริ่ม/ปิดรับราคา/ยื่นทัน) ต้องใช้ **เวลาของเซิร์ฟเวอร์** เท่านั้น นับถอยหลังบนเบราว์เซอร์เป็นเพียงการแสดงผล | ✅ |
| NFR-04 | ราคาที่ยื่นต้องไม่รั่วไปยังผู้ใช้อื่น ในทุกช่องทาง (HTML, JSON, Turbo Stream, log, ข้อความ error) มี test ครอบ | ✅ |
| NFR-05 | กติกา "ยื่นครั้งเดียว" ต้องบังคับที่ระดับฐานข้อมูล (unique) ด้วย ไม่ใช่แค่ validation ในโค้ด — การยิง request ซ้ำพร้อมกันต้องสำเร็จได้เพียงครั้งเดียว | ✅ |
| NFR-06 | การปิดประมูลต้องทำงานอัตโนมัติผ่าน background job และมีกลไกกวาดซ้ำเมื่อ job หลุดหรือเซิร์ฟเวอร์รีสตาร์ท | ✅ |
| NFR-07 | password ต้องเก็บแบบ hash (ไม่เก็บ plain text) และหน้า login ต้องมี rate limit | ✅ |
| NFR-08 | ทุก request ต้องตรวจสิทธิ์ฝั่ง server: admin เข้าได้เฉพาะ role admin · ผู้ใช้ที่ยังไม่ผ่านตรวจเข้าได้เฉพาะหน้าสถานะ | ✅ / ✅ |
| NFR-09 | เงินต้องเก็บเป็นจำนวนเต็มหรือ decimal ห้ามใช้ float | ✅ |
| NFR-10 | UI ต้องใช้ component และ token ตาม [DESIGN.md](../DESIGN.md) | ✅ |
| NFR-11 | ช่องกรอกทุกช่องต้องมี label, ข้อความ error แสดงใต้ช่อง, สถานะโหลด/ว่าง/ผิดพลาดต้องแสดงเสมอ | ✅ (ตามมาตรฐาน UI) |
| NFR-12 | UI ต้องใช้งานได้บนหน้าจอมือถือและเดสก์ท็อป (ผู้ใช้ยื่นราคาใน 30 วินาทีอาจใช้มือถือ) | ✅ |
| NFR-13 | การกระทำที่ย้อนกลับไม่ได้ (ลบ, อนุมัติ, ไม่ผ่านตรวจ, ยกเลิก event) ต้องมีขั้นยืนยัน | ✅ (ตามมาตรฐาน UI) |
| NFR-14 | ทุก requirement ที่เป็นกติกาประมูล (BID-*) ต้องมี automated test | ✅ |
| NFR-15 | โค้ดต้องผ่าน rubocop และ brakeman ก่อน merge | ✅ |
| NFR-16 | ประสิทธิภาพ: ต้องรองรับจำนวนผู้ประมูลพร้อมกันตามเป้าหมายที่ตกลง (ยังไม่กำหนด ดู O-3) | ✅ ดู open item |
| NFR-17 | **Audit log:** ทุกการกระทำของ admin ที่เปลี่ยนข้อมูลหรือเปิดดูข้อมูลลับต้องถูกบันทึก อย่างน้อย: สร้าง/แก้/ลบ/เก็บถาวร/อนุมัติสินค้า (รวมค่าราคาเดิม→ใหม่), สร้าง/แก้/ยกเลิก event, ผ่าน/ไม่ผ่านคุณสมบัติ, ระงับ/ยกเลิกระงับ, รีเซ็ตรหัสผ่าน, สร้าง/ปิด/เปิดใช้งาน admin, เปิด/ปิดวิธีประมูล, **เปิดดูราคาที่ยื่น** (EVT-12) · แต่ละรายการเก็บ admin ผู้ทำ, เวลา, ประเภทการกระทำ, สิ่งที่ถูกกระทำ, ค่าก่อน/หลัง (ถ้ามี), เหตุผล (ถ้ามี) | ⚠️ |
| NFR-18 | audit log ต้อง **เพิ่มได้อย่างเดียว** (ไม่มีหน้าหรือ route แก้/ลบ) และ admin ต้องดูได้ กรองตาม admin / ประเภทการกระทำ / ช่วงเวลา / สิ่งที่ถูกกระทำ · log ห้ามเก็บรหัสผ่านหรือรหัสชั่วคราว | ⚠️ |
| NFR-19 | **ห้ามลบข้อมูลประวัติ:** ราคาที่ยื่น, การเข้าร่วม, lot และผล, รอบส่งทรัพย์สิน, ประวัติระงับ และ audit log ต้องไม่ถูกลบ ทั้งโดยตรงและโดย cascade จากการลบสินค้า/ห้อง/event/บัญชี · ระเบียนที่มีประวัติเหล่านี้ใช้ "เก็บถาวร" หรือ "ปิดใช้งาน" แทนการลบ (ITEM-12, ROOM-05, EVT-11, ADM-06) และบังคับที่ระดับฐานข้อมูลด้วย (foreign key แบบ restrict) | ⚠️ |
