# 04 กติกาการประมูล First-Price Sealed Bid

## BID

| รหัส | Requirement | สถานะ |
|---|---|---|
| BID-01 | ผู้ใช้ยื่นราคาได้ **ครั้งเดียวต่อสินค้า** ยื่นแล้ว **แก้ไขและถอนไม่ได้** | ✅ |
| BID-02 | เมื่อการประมูลเริ่ม (เวลาเริ่มของ event) ระบบต้องรับราคาเป็นเวลา **30 วินาที** หลังจากนั้นต้องปฏิเสธการยื่นราคา | ✅ |
| BID-03 | ผู้ใช้ต้องผ่านการตรวจคุณสมบัติ ไม่ถูกระงับ และต้องเข้าร่วมประมูลสินค้านั้นไว้ก่อน จึงยื่นราคาได้ | ✅ (เข้าร่วมก่อน) |
| BID-04 | ราคาที่ยื่นต้อง **ไม่เกินมูลค่าทรัพย์สินรวม** ที่ผู้ใช้แจ้งและผ่านตรวจแล้ว (ตรวจต่อครั้ง ไม่รวมสะสมข้ามสินค้า) | ✅ (เพดาน) / ⚠️ (ต่อครั้ง) |
| BID-05 | ราคาที่ยื่นต้อง **ไม่ต่ำกว่าราคาเริ่มต้น** ของสินค้า และเป็นจำนวนเงินบาทมากกว่า 0 | ⚠️ |
| BID-06 | เมื่อครบเวลา ระบบต้อง **คำนวณผู้ชนะอัตโนมัติ** ผู้ที่ยื่นราคาสูงสุดชนะ (จ่ายตามราคาที่ตนยื่น) | ✅ |
| BID-07 | หากราคาสูงสุดเท่ากัน ผู้ที่ **ยื่นก่อน** (เวลาที่บันทึกเร็วกว่า) ชนะ | ✅ |
| BID-08 | ราคาสูงสุดต้อง **ไม่ต่ำกว่าราคาขั้นต่ำ (reserve)** จึงถือว่ามีผู้ชนะ | ✅ |
| BID-09 | หากไม่มีผู้ยื่นราคา หรือราคาสูงสุดต่ำกว่าราคาขั้นต่ำ ให้ **จบการประมูลโดยไม่ขาย** สินค้ากลับเป็น "พร้อมขาย" | ✅ (ไม่ขาย) / ⚠️ (กลับพร้อมขาย + กรณีต่ำกว่า reserve) |
| BID-10 | เมื่อมีผู้ชนะ สินค้าต้องเปลี่ยนเป็น "ขายได้แล้ว" (ใน M1 ตั้งตอนประกาศผู้ชนะ) | ⚠️ |
| BID-11 | **เฉพาะ admin** เห็นราคาที่ยื่นของทุกคนได้ ผู้ใช้เห็นเฉพาะราคาของตนเอง | ✅ |
| BID-12 | หลังจบ ระบบต้องเปิดเผย **ราคาผู้ชนะ** แก่ผู้ใช้ แต่ต้องไม่เปิดเผยตัวตนผู้ชนะ | ✅ |
| BID-13 | ระบบต้องเก็บประวัติราคาที่ยื่นทั้งหมดพร้อมเวลาที่ยื่น (ละเอียดระดับมิลลิวินาที) ไม่ลบ | ⚠️ |
| BID-14 | การปิดการประมูลและคำนวณผู้ชนะต้อง **ทำซ้ำได้โดยผลไม่เปลี่ยน** (รัน job ซ้ำไม่ทำให้ผู้ชนะ/สถานะเปลี่ยน) | ⚠️ |
| BID-15 | วิธีประมูลผูกกับ event: ทุกสินค้าใน event ใช้กติกาของวิธีประมูลเดียวกัน | ✅ |
| BID-16 | ทุกสินค้าใน event เริ่มและปิดรับราคาพร้อมกัน (นับจากเวลาเริ่มของ event) | ⚠️ ดู open item O-1 |
| BID-17 | ~~ราคาของผู้ใช้ที่ถูกระงับก่อนปิดรับราคา ต้องไม่นับในการคัดผู้ชนะ~~ **แก้ไข:** ราคาที่ยื่นไว้แล้ว **นับตามปกติ** แม้ผู้ยื่นถูกระงับในภายหลัง (ตาม SUSP-04 ฉบับแก้) หน้า admin แสดงป้าย "บัญชีถูกระงับ" ข้างราคานั้น · การคัดผู้ชนะไม่ขึ้นกับสถานะระงับเลย ทำให้ผลไม่เปลี่ยนตามการกระทำของ admin ระหว่างเปิดรับราคา | ⚠️ (แก้จาก ✅ เดิม รอเจ้าของโปรเจคยืนยันใหม่) |
| BID-18 | **ราคาขั้นต่ำ (reserve) เป็นความลับ** ผู้ใช้ต้องไม่เห็นค่า และไม่รู้แม้แต่ว่าสินค้ามี reserve สูงกว่าราคาเริ่มต้นหรือไม่ ในทุกช่องทาง (HTML, JSON, Turbo Stream, log, ข้อความ error) เช่นเดียวกับ `NFR-04` | ⚠️ |
| BID-19 | เมื่อสินค้า **ไม่ขาย** ผู้ใช้เห็นเพียงคำว่า "ไม่ขาย" ต้อง **ไม่** เปิดเผย ราคาสูงสุดที่ยื่น จำนวนผู้ยื่น หรือเหตุผล (ไม่มีผู้ยื่น / ต่ำกว่า reserve) — ราคาผู้ชนะ (BID-12) แสดงเฉพาะกรณีขายได้ | ⚠️ |
| BID-20 | ก่อนส่งราคา ต้องมี **ขั้นยืนยัน 1 คลิก** ที่แสดงจำนวนเงินตัวเลขใหญ่ คั่นหลักพัน พร้อมหน่วย "บาท" และข้อความว่า "ยื่นแล้วแก้ไขหรือถอนไม่ได้" · ขั้นยืนยันไม่ขยายเวลา ถ้ากดยืนยันหลังหมดเวลาต้องถูกปฏิเสธตาม BID-02 | ⚠️ |
| BID-21 | ฟอร์มยื่นราคาต้องแสดง **ช่วงราคาที่ยื่นได้** (ราคาเริ่มต้น ถึง เพดานทรัพย์สินรวมของผู้ใช้) และตรวจช่วงราคาฝั่งเบราว์เซอร์ก่อนส่ง เพื่อไม่ให้เสียเวลาใน 30 วินาที (server ยังเป็นผู้ตัดสินตาม BID-04/05) | ⚠️ |

## ตัวอย่างสถานการณ์ (ใช้เป็นกรณีทดสอบ)

สินค้า A: ราคาเริ่มต้น 1,000 บาท ราคาขั้นต่ำ 1,500 บาท

| ผู้ใช้ | ทรัพย์สินรวม | ราคาที่ยื่น | ผล |
|---|---|---|---|
| ก | 5,000 | 1,800 (เวลา 10:00:05.200) | ชนะ จ่าย 1,800 |
| ข | 5,000 | 1,800 (เวลา 10:00:09.700) | แพ้ (ราคาเท่ากัน ยื่นช้ากว่า) |
| ค | 1,200 | 2,000 | **ถูกปฏิเสธ** (เกินทรัพย์สินรวม BID-04) |
| ง | 3,000 | 900 | **ถูกปฏิเสธ** (ต่ำกว่าราคาเริ่มต้น BID-05) |
| ก (ยื่นซ้ำ) | — | 2,500 | **ถูกปฏิเสธ** (ยื่นได้ครั้งเดียว BID-01) |
| จ | 5,000 | 1,600 (เวลา 10:00:31) | **ถูกปฏิเสธ** (เกิน 30 วินาที BID-02) |

ผู้ใช้ทุกคนที่เข้าร่วมเห็นว่าราคาผู้ชนะคือ 1,800 โดยไม่เห็นว่าใครชนะ · ถ้าราคาสูงสุดที่ยื่นคือ 1,400 → ไม่ขาย (ต่ำกว่า 1,500) สินค้ากลับ "พร้อมขาย" และผู้ใช้เห็นเพียง "ไม่ขาย" ไม่เห็น 1,400 หรือ 1,500 (BID-18/19) · ถ้า admin ระงับผู้ใช้ ก ระหว่างช่วงเปิดรับราคา ก ยังชนะที่ 1,800 (BID-17)
