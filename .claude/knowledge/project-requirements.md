# Auction Devpool — Requirement (จากผู้ใช้ 2026-11-11)

ระบบประมูลสินค้า รองรับหลายวิธีประมูลในอนาคต (english, first-price, dutch ฯลฯ)
**Milestone 1 = first-price sealed bid เท่านั้น** ภาษาไทย สกุลเงินบาท

## กติกา first-price sealed (ตัดสินใจแล้ว)
- เสนอราคาได้ **ครั้งเดียว แก้ไม่ได้** ภายในเวลาที่กำหนด **ไม่เกิน 30 วินาที** (ความหมายเวลา 30 วิ ยังต้องยืนยัน ดูข้อค้างด้านล่าง)
- สินค้ามี **ราคาเริ่มต้น** และ **ราคาขั้นต่ำ (reserve)** ที่ admin กำหนดตอนเพิ่มสินค้า
- ไม่มีใครเสนอ (หรือไม่ถึงขั้นต่ำ) → จบการประมูล สินค้า **ยังไม่ถูกขาย**
- **เฉพาะ admin** เห็นราคาที่ทุกคนเสนอ · เมื่อจบ **เปิดเผยราคาผู้ชนะ** ให้ผู้ใช้เห็น แต่ **ไม่บอกว่าใครชนะ**
- ราคาเท่ากัน → **ผู้เสนอก่อนชนะ** (ต้องเก็บ timestamp ละเอียด)
- **ระบบคำนวณผู้ชนะอัตโนมัติ** เมื่อสิ้นสุด
- หน้าผู้ใช้แสดง "ราคา" = **ราคาเริ่มต้น**
- ราคาที่เสนอ **ต้องไม่เกินมูลค่าทรัพย์สินที่ผู้ใช้แจ้ง**

## ความสัมพันธ์ข้อมูล
- สินค้า 1 ชิ้นอยู่ได้ **event เดียว**
- ห้องประมูล: "จำนวนคน" = **จำนวนผู้เข้าร่วมประมูลทั้งหมด** (ไม่ใช่พร้อมกัน); "จำนวนสินค้า" = สูงสุดที่ใส่ใน event ของห้องนั้นได้
- "เข้าร่วมประมูล" = ลงทะเบียนสนใจสินค้า (ทำก่อนเสนอราคา) · "เข้าห้อง" = เข้าไปตอนถึงเวลาจริง
- **วิธีประมูลผูกกับ event** · admin ดู/เพิ่ม/**เปิด-ปิด** วิธีประมูลได้ (milestone 1 มี first-price)
- สถานะสินค้า: รออนุมัติ → พร้อมขาย → อยู่ระหว่างการประมูล → ขายได้แล้ว
- สินค้ามี **หลายรูป**

## ส่วน Admin
- login: username + password · admin **สร้างบัญชี admin อื่นได้** · มี **ระดับเดียว** (ไม่แยกสิทธิ์)
- Module: (1) สินค้าประมูล ดู/เพิ่ม/แก้/ลบ/อนุมัติ · (2) วิธีการประมูล · (3) ห้องประมูล (ชื่อ รายละเอียด จำนวนคน จำนวนสินค้า) · (4) การประมูล/event (ชื่อ ห้อง เวลาเริ่ม-สิ้นสุด สินค้า)
- **ต้องมี module ตรวจสอบคุณสมบัติผู้ใช้** (ผ่าน/ไม่ผ่าน) ซึ่งยังไม่ได้อยู่ในรายการ module เดิม
- banner โฆษณา: ไม่ต้องจัดการได้ใน milestone 1

## ส่วนผู้ใช้
- login: username + password · register: fullname, username, password, email → สถานะ "รอการตรวจสอบคุณสมบัติ"
- เข้าระบบแล้วกรอก **ทรัพย์สิน เป็นรายการ (ชื่อ + มูลค่าเป็นตัวเลข) ไม่แนบเอกสาร** → submit → **รอ admin ตรวจ ผ่าน/ไม่ผ่าน** (เปลี่ยนจากที่เคยบอกว่าเข้าได้เลย)
- ไม่ต้องยืนยัน email และยังไม่ต้องมี "ลืมรหัสผ่าน" (milestone 2)
- หน้าแรก: รายการสินค้า + banner (ของคงที่) แสดงเวลาประมูล ราคาเริ่มต้น → คลิกดูรายละเอียด → เข้าร่วมประมูล → ถึงเวลาเข้าห้อง ดูสินค้าในห้อง และเข้าร่วมเพิ่มได้
- **หน้าผลการประมูล**: รายการสินค้าที่เข้าร่วม + ชนะ/ไม่ชนะ · ถ้าชนะกดไป **ชำระเงินภายในเวลาที่กำหนด** → ชำระแล้วเข้าสู่ **ขั้นตอนส่งมอบ**
- แจ้งเตือน: ดูที่หน้าผู้ใช้เอง (ไม่มี email/push)

## ตัดสินใจรอบสอง (2026-11-11)
- เวลา 30 วินาที = **เมื่อเริ่มประมูลแล้ว มีเวลา 30 วินาทีในการยื่นราคา**
- **ชำระเงินและส่งมอบย้ายไป Milestone 2** (M1 จบที่ผู้ใช้เห็นผลชนะ/ไม่ชนะ + ราคาผู้ชนะ)
- ข้อ 3–7 ที่ยังไม่ได้ตอบ ผมตั้งเป็นสมมติฐานไว้ใน `docs/milestone-1.md` หัวข้อ 9 (รอเจ้าของโปรเจคยืนยัน)
- แผนงานและ acceptance criteria อยู่ที่ `docs/milestone-1.md` (6 ขั้น)
- **ผู้ใช้ที่ยังไม่ผ่านตรวจ (ยังไม่กรอก/รอตรวจ/ไม่ผ่าน) ทำอะไรไม่ได้เลย** เห็นเฉพาะหน้าสถานะ (ไม่ใช่ดูสินค้าได้แต่เข้าร่วมไม่ได้ ตามที่เคยสมมติ) · ใช้ before_action กลางส่งไปหน้าสถานะ
- **Requirement ฉบับทางการอยู่ที่ `requirements/`** (README + 01–07, มีรหัสอ้างอิง AUTH/QUAL/ITEM/METH/ROOM/EVT/USR/BID/NFR/OOS และสถานะ ✅ยืนยัน/⚠️สมมติฐาน) · ข้อที่ยังรอตัดสินใจอยู่ `requirements/07-open-items.md` (O-1 ความหมาย ends_at สำคัญสุด) · ไฟล์นี้เป็นบันทึกดิบ ถ้าขัดกันให้ถือ `requirements/` เป็นหลัก
