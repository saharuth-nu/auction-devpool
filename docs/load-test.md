# ผลทดสอบโหลดการยื่นราคา (NFR-16, O-3, O-4)

วัดด้วย `test/services/place_bid_load_test.rb` (รันด้วย `VERBOSE_LOAD=1 bin/rails test test/services/place_bid_load_test.rb`)
และความถูกต้องภายใต้การยื่นพร้อมกันด้วย `test/services/place_bid_concurrency_test.rb` (NFR-05)

| รายการ | ผล (เครื่องพัฒนา, SQLite) |
|---|---|
| 150 คนยื่นราคาใน lot เดียวในหน้าต่าง 30 วินาที | ครบ 150 รายการ ใช้ราว 0.4 วินาที (ราว 360 รายการ/วินาที) |
| ผู้ชนะ | ถูกต้อง (ราคาสูงสุด) |
| ยื่นพร้อมกันหลาย thread | ไม่มีการยื่นซ้ำ unique index เป็นตัวกันสุดท้าย |

## ข้อสรุปเบื้องต้น
- **O-3:** ค่านี้วัดบนเครื่องเดียว ยังไม่ได้ตั้งเป้าผู้ใช้พร้อมกันจากเจ้าของโปรเจค ตัวเลขข้างบนเป็นเพียงเส้นฐาน
- **O-4:** SQLite เขียนได้ทีละรายการ แต่การยื่นราคาเป็นการเขียนสั้นๆ จึงรองรับได้ถึงระดับร้อยคนต่อหน้าต่าง 30 วินาทีสบาย
  หากเป้าหมายจริงเป็นหลักพันคนพร้อมกัน หรือต้องใช้หลายเครื่อง ควรย้ายไป PostgreSQL (เปลี่ยนที่ config/database.yml และ migrate ข้อมูล)
- การทดสอบนี้ไม่ได้วัดผ่าน HTTP/เครือข่ายจริง ถ้าจะยืนยันก่อนใช้งานจริงควรทดสอบโหลดกับ server production (เช่น k6) ด้วย
