# Milestone 1 — ระบบประมูลแบบ First-Price Sealed Bid

เอกสารนี้เป็นแผนของ milestone แรก สรุปจาก requirement ที่ตกลงกันแล้ว (บันทึกดิบอยู่ที่ `.claude/knowledge/project-requirements.md`)
Requirement ฉบับละเอียดมีรหัสอ้างอิงอยู่ที่ [requirements/](../requirements/README.md) (ถ้าขัดกับเอกสารนี้ให้ถือ requirements/ เป็นหลัก)
หัวข้อ 9 คือ **สมมติฐานที่ผมตั้งเอง** ต้องให้เจ้าของโปรเจคยืนยันก่อนเริ่มงานส่วนที่เกี่ยวข้อง

## 1. เป้าหมาย

ผู้ใช้ที่ผ่านการตรวจสอบคุณสมบัติแล้ว สามารถเข้าร่วมการประมูลสินค้า ยื่นราคาลับได้ครั้งเดียวภายใน 30 วินาที
และเมื่อหมดเวลา ระบบหาผู้ชนะให้อัตโนมัติ ผู้ใช้เห็นผลว่าชนะหรือไม่ และเห็นราคาที่ชนะ (ไม่เห็นว่าใครชนะ)
admin จัดการสินค้า ห้อง การประมูล ผู้ใช้ และเห็นราคาที่ทุกคนยื่นทั้งหมด

ภาษาไทย สกุลเงินบาท ใช้ UI ตาม [DESIGN.md](../DESIGN.md) (helper `ui_*`)

## 2. ขอบเขต

**อยู่ใน Milestone 1**
- Login admin / login ผู้ใช้ / register ผู้ใช้
- Admin: จัดการสินค้า (+อนุมัติ, หลายรูป), วิธีประมูล, ห้อง, การประมูล (event), ตรวจสอบคุณสมบัติผู้ใช้, สร้างบัญชี admin
- ผู้ใช้: กรอกทรัพย์สิน, หน้าแรก (รายการสินค้า + banner คงที่), รายละเอียดสินค้า, เข้าร่วมประมูล, ห้องประมูล, ยื่นราคา, หน้าผลการประมูล
- ระบบปิดประมูลและหาผู้ชนะอัตโนมัติ

**ไม่อยู่ใน Milestone 1 (ย้ายไป Milestone 2)**
- ชำระเงิน และขั้นตอนส่งมอบ (ผู้ใช้ที่ชนะเห็นผลชนะ แต่ยังไม่มีปุ่มชำระเงิน)
- ยืนยัน email, ลืมรหัสผ่านแบบทำเองผ่าน email (ใน M1 ใช้ admin รีเซ็ตรหัสผ่านให้แทน)
- วิธีประมูลอื่น (english, dutch) — ออกแบบให้เพิ่มได้ แต่ยังไม่ทำ
- admin หลายระดับสิทธิ์, จัดการ banner, แจ้งเตือนทาง email/push

## 4. กติกาการประมูล (first-price sealed)

1. ผู้ประมูลยื่นราคา **ได้ครั้งเดียวต่อสินค้า แก้/ถอนไม่ได้**
2. เมื่อการประมูลเริ่ม (`starts_at` ของ event) มีเวลา **30 วินาที** ในการยื่นราคา ค่า 30 วินาทีเก็บเป็นค่ากำหนดของวิธีประมูล ไม่ฝังในโค้ดหลายที่
3. ราคาที่ยื่นต้อง **≥ ราคาเริ่มต้น** และ **≤ มูลค่าทรัพย์สินรวมที่ผู้ใช้แจ้ง**
4. สินค้ามี **ราคาเริ่มต้น** และ **ราคาขั้นต่ำ (reserve)** ที่ admin ตั้งตอนเพิ่มสินค้า (reserve ≥ ราคาเริ่มต้น)
5. หมดเวลาแล้ว ระบบหาผู้ชนะอัตโนมัติ: ราคาสูงสุดชนะ ราคาเท่ากัน **ยื่นก่อนชนะ**
6. ถ้าไม่มีใครยื่น หรือราคาสูงสุดต่ำกว่า reserve → **ไม่ขาย** สินค้ากลับไปเป็น "พร้อมขาย"
7. ความลับของราคา: **เฉพาะ admin** เห็นราคาที่ยื่นของทุกคน (ผู้ใช้เห็นเฉพาะราคาที่ตัวเองยื่น) หลังจบ ผู้ใช้ทุกคนเห็น **ราคาผู้ชนะ** แต่ไม่เห็นว่าใครชนะ
8. หน้าผู้ใช้แสดง "ราคา" ของสินค้าเป็น **ราคาเริ่มต้น**

## 6. สถานะ

**สินค้า:** `รออนุมัติ` → (admin อนุมัติ) `พร้อมขาย` → (ถูกใส่ใน event ที่เริ่มแล้ว) `อยู่ระหว่างการประมูล` → (มีผู้ชนะ) `ขายได้แล้ว` · ไม่ขาย → กลับ `พร้อมขาย` และออกจาก event
สินค้าอยู่ได้ **event เดียวในเวลาเดียว** · ลบ/แก้ราคาสินค้าที่อยู่ระหว่างประมูลไม่ได้

**ผู้ใช้:** `รอกรอกทรัพย์สิน` → `รอ admin ตรวจ` → `ผ่าน` | `ไม่ผ่าน` (→ แก้แล้วกลับเป็น `รอ admin ตรวจ`) · ค่าในระบบ `awaiting_assets` `awaiting_review` `approved` `rejected` (ดู requirements/01-accounts.md)

**Event:** `ยังไม่เริ่ม` → `เปิดรับราคา` (30 วินาที) → `ปิดรับราคา/สรุปผลแล้ว` · ยกเลิกได้ก่อนเริ่ม

## 8. ข้อกำหนดทางเทคนิคที่สำคัญ

- **เวลาใช้เวลาของเซิร์ฟเวอร์เท่านั้น** ตรวจ `placed_at ≤ starts_at + bidding_seconds` ที่ server ทุกครั้ง นับถอยหลังฝั่งเบราว์เซอร์เป็นแค่การแสดงผล
- **ปิดประมูลด้วย Solid Queue job** ตั้งเวลาที่ `starts_at + bidding_seconds` และมี job กวาดซ้ำใน `config/recurring.yml` กรณี job หลุด/เซิร์ฟเวอร์รีสตาร์ท การปิดต้อง idempotent (รันซ้ำไม่เปลี่ยนผล) ทำใน transaction
- **ห้ามรั่วราคาลับ:** ไม่ส่งราคาของคนอื่นไปหน้าผู้ใช้ทุกช่องทาง (HTML, JSON, Turbo Stream, log) ครอบด้วย test
- **สิทธิ์:** ทุก controller ฝั่ง admin ตรวจ role = admin, ฝั่งผู้ใช้ใช้ `before_action` กลางตัวเดียวที่ส่งผู้ใช้ซึ่งยังไม่ผ่านตรวจไปหน้าสถานะ (อนุญาตเฉพาะหน้าสถานะ/ส่งทรัพย์สิน/logout) ทุก controller ฝั่งผู้ใช้จึงปลอดภัยโดยค่าเริ่มต้น ไม่ต้องตรวจทีละหน้า
- **กันยื่นซ้ำ/ยื่นพร้อมกัน:** unique index + จับ `RecordNotUnique` แสดงข้อความ "คุณยื่นราคาแล้ว"
- **รหัสผ่าน:** `has_secure_password` (bcrypt) ไม่เก็บ plain text, rate limit หน้า login
- เวลาที่แสดงใช้เขตเวลา `Asia/Bangkok`, ตั้ง locale `th`

## 9. สมมติฐานที่ตั้งเอง (ยืนยันด้วย)

1. **เวลา 30 วินาที:** ทุกสินค้าใน event เริ่มและปิดรับราคาพร้อมกัน นับจาก `starts_at` ของ event · `ends_at` ที่ admin กรอกคือเวลาปิดห้อง (หลังจากนั้นเข้าห้องไม่ได้) ไม่ใช่เวลาปิดรับราคา
2. ~~ผู้ใช้ที่ยังไม่ผ่านตรวจดูสินค้าได้~~ **ยืนยันแล้ว: ยังไม่ผ่านตรวจ = ทำอะไรไม่ได้เลย เห็นแค่หน้าสถานะ**
3. ไม่ผ่านตรวจ → แก้ทรัพย์สินและส่งใหม่ได้ ผู้ใช้เห็นเหตุผล (ยังเป็นสมมติฐาน)
4. วงเงิน **ต่อครั้ง**: ราคาแต่ละรายการไม่เกินมูลค่าทรัพย์สินรวม (ไม่นับสะสมข้ามสินค้า)
5. ห้องเต็มตาม `max_participants` → ปุ่มเข้าร่วมกดไม่ได้ (นับเฉพาะ event นั้น)
6. สินค้าไม่ขาย → กลับเป็น "พร้อมขาย" ออกจาก event เพื่อนำไปใส่ event ใหม่ได้
7. "ขายได้แล้ว" ตั้งตอนระบบประกาศผู้ชนะ (ใน M2 ที่มีชำระเงินอาจเปลี่ยนเป็นหลังชำระเสร็จ)
8. เก็บประวัติราคาที่ยื่นทั้งหมดไว้ ไม่ลบ
9. admin คนแรกสร้างจาก seed (`db/seeds.rb`) ไม่มีหน้า register ของ admin
10. banner หน้าแรกเป็นรูป/ข้อความคงที่ในโค้ด

## 10. แผนงาน (ลำดับและ acceptance criteria)

ขั้น 1 ต้องทำก่อน ขั้น 2 กับ 3 ทำขนานกันได้ ขั้น 4 ต้องรอขั้น 2 และ 3

### ขั้น 1 — รากฐาน
- Authentication (generator ของ Rails 8), role admin/bidder, layout ใช้ design system, locale th + เขตเวลา Bangkok, seed admin คนแรก + วิธีประมูล first_price
- ✅ login/logout ทั้งสองฝั่งได้ · เข้า `/admin` โดยไม่ใช่ admin ไม่ได้ · มี test

### ขั้น 2 — Admin: ข้อมูลหลัก
- CRUD สินค้า (+หลายรูป, อนุมัติ, ตัวกรองสถานะ), วิธีประมูล (เปิด/ปิด), ห้อง, บัญชี admin
- ✅ สร้างสินค้าแล้วอยู่สถานะ "รออนุมัติ" · อนุมัติแล้วเป็น "พร้อมขาย" · reserve < ราคาเริ่มต้นแล้ว error · ลบสินค้าที่อยู่ระหว่างประมูลไม่ได้

### ขั้น 3 — ผู้ใช้: register และตรวจสอบคุณสมบัติ
- register, กรอกทรัพย์สิน, หน้า admin ตรวจผู้ใช้ (ผ่าน/ไม่ผ่าน+เหตุผล), ส่งตรวจใหม่
- ✅ register แล้วสถานะ "รอกรอกทรัพย์สิน" · ผู้ใช้ที่ไม่ใช่สถานะ "ผ่าน" เปิด URL ใดก็ตามของฝั่งผู้ใช้ (หน้าแรก สินค้า ห้อง ผลประมูล และ request ยื่นราคา) ถูกส่งกลับหน้าสถานะทั้งหมด · ไม่ผ่านแล้วเห็นเหตุผลและส่งใหม่ได้ · ผ่านแล้วเข้าหน้าแรกได้

### ขั้น 4 — การประมูล (event) และฝั่งผู้ใช้
- CRUD event (เลือกห้อง/วิธี/สินค้าไม่เกินที่ห้องรองรับ ไม่เลือกสินค้าที่อยู่ event อื่น), หน้าแรก, รายละเอียดสินค้า, เข้าร่วมประมูล, ห้องประมูล
- ✅ ใส่สินค้าเกินที่ห้องรองรับไม่ได้ · สินค้า 1 ชิ้นอยู่ 2 event พร้อมกันไม่ได้ · ห้องเข้าได้ตอนถึงเวลา · ห้องเต็มแล้วเข้าร่วมไม่ได้

### ขั้น 5 — ยื่นราคา ปิดประมูล และผลลัพธ์ (หัวใจของ milestone)
- ยื่นราคา (ครั้งเดียว, ในเวลา, ช่วงราคาที่ถูกต้อง), นับถอยหลัง, job ปิดประมูลและหาผู้ชนะ, หน้าผลการประมูลฝั่งผู้ใช้, หน้า admin ดูราคาที่ยื่นทั้งหมด
- ✅ ยื่นครั้งที่สองไม่ได้ (แม้ยิงพร้อมกัน) · ยื่นหลัง 30 วินาทีไม่ได้ · ราคาเกินทรัพย์สิน/ต่ำกว่าราคาเริ่มต้นไม่ได้ · ราคาเท่ากันคนยื่นก่อนชนะ · ต่ำกว่า reserve หรือไม่มีคนยื่น = ไม่ขายและสินค้ากลับ "พร้อมขาย" · รัน job ปิดซ้ำแล้วผลไม่เปลี่ยน · ผู้ใช้ไม่เห็นราคาของคนอื่น/ตัวตนผู้ชนะในทุกหน้า

### ขั้น 6 — ปิดงาน
- ไล่ทดสอบทั้ง flow ด้วยบัญชีจริงหลายคน, system test ของ flow หลัก, brakeman/rubocop ผ่าน, เอกสารวิธีรัน
- ✅ จำลอง event ที่มีผู้ประมูล ≥ 3 คน ตั้งแต่ register ถึงเห็นผล ผ่านทั้งหมด

## 11. เรื่องที่รอตัดสินใจใน Milestone 2
ชำระเงิน (gateway จริงหรือ admin ยืนยัน, กำหนดเวลา, ผู้ชนะไม่จ่าย), ส่งมอบ (สถานะ, เลขพัสดุ), ยืนยัน email, ลืมรหัสผ่าน, วิธีประมูลอื่น
